# اجرای میز تست مرحله‌به‌مرحلهٔ صوت (وب)

این صفحه یک **میز تست** است، نه محصول: هر قطعهٔ زنجیرهٔ صوت را **مستقل** از بقیهٔ
اجرا می‌کند تا معلوم شود نقص از «گوش» (میکروفون/Whisper) است، از «مغز» (llama.cpp)
یا از «دهان» (Piper):

1. **ضبط و رونویسی** — میکروفون → `POST /api/transcribe` → فقط Whisper؛ نه LLM، نه TTS.
2. **تنظیمات ASR** — همان آخرین ضبط دوباره با `beam_size`/`language`/`initial_prompt`
   دلخواه رونویسی می‌شود (`use_last: true`)؛ مقایسهٔ تنظیمات روی **یک فایل صوتی ثابت**،
   بدون اینکه گوینده جمله را تکرار کند. لینک دانلود ضبط: `GET /api/last.wav`.
3. **مدل** — `POST /api/chat`؛ متن → llama.cpp → فقط پاسخ متنی + `llm_ms` و تعداد توکن.
4. **صدا** — `POST /api/tts`؛ هر متنی → Piper → WAV پخش‌شونده؛ هیچ درخواستی به مدل نمی‌رود.

## پیش‌نیازها

1. llama-server در حال اجرا باشد (مثلاً `.\tools\start_llama.ps1 -Exe D:\Lama.cpp\bin\llama-server.exe`).
2. `.env` مثل مسیر صوت PC تنظیم شده باشد (مدل Whisper، Piper، آدرس llama-server).

## اجرا

```powershell
.\tools\start_webui.ps1          # یا: python -m server.webui --port 8100
```

سپس در مرورگر همین ماشین باز کنید: <http://127.0.0.1:8100>

## چه چیزی را نشان می‌دهد

| بخش | توضیح |
|---|---|
| وضعیت | ASR/TTS: «بارگذاری…» تا وقتی مدل Whisper در پس‌زمینه لود شود (حدود یک دقیقه روی CPU دوهسته‌ای) |
| دکمهٔ میکروفون | نگه دار و صحبت کن؛ روی رهاکردن، PCM16/16kHz (رزنپل درست‌تر با `OfflineAudioContext`) به `POST /api/transcribe` می‌رود |
| آمار ضبط | `seconds`/`rms_dbfs`/`peak_dbfs`/`speech_ratio` از `pcm_stats` سمت سرور؛ صدای خیلی ضعیف (< −۴۵ dBFS) یا clip (peak > −۰٫۵ dBFS) هشدار می‌گیرد |
| رونویسی | متن شنیده‌شده، **قابل ویرایش**؛ دکمهٔ «پر کردن از رونویسی» آن را به بخش مدل می‌برد |
| تنظیمات ASR | `beam_size` (۱/۳/۵)، `language` (fa/auto)، `initial_prompt`؛ نتیجهٔ هر بار در «رونویسی دوباره» مقایسه می‌شود |
| مدل | پاسخ متنی + `llm_ms`/`prompt_tokens`/`completion_tokens`؛ «پر کردن از پاسخ مدل» متن را به بخش صدا می‌برد |
| صدا | پخش خودکار WAV برگشتی از Piper + `tts_ms` |
| شروع تازه | تاریخچهٔ کوتاه پنجره‌ای RAM (۱۲ پیام) و همهٔ جعبه‌ها را پاک می‌کند |

## قرارداد API

| متد | مسیر | ورودی | خروجی |
|---|---|---|---|
| `POST` | `/api/transcribe` | `{"pcm_b64": "<base64 PCM16 mono 16kHz>"}` یا `{"use_last": true, "beam_size": 5, "language": "fa", "initial_prompt": "..."}` | `transcript`, `timings.asr_ms`, `audio` (آمار ضبط) |
| `GET` | `/api/last.wav` | — | آخرین ضبط به‌صورت WAV (برای بازرسی/مقایسه بیرون از مرورگر) |
| `POST` | `/api/chat` | `{"text": "..."}` | `reply`, `timings` (`llm_ms`, توکن‌ها) |
| `POST` | `/api/tts` | `{"text": "..."}` | `tts_wav_b64`, `timings.tts_ms` |
| `POST` | `/api/turn` | `{"text": "..."}` یا `{"pcm_b64": ...}` (مسیر یک‌چرخه‌ای قدیمی) | `transcript`, `reply`, `tts_wav_b64`, `timings` |
| `POST` | `/api/reset` | — | `{"status": "ok"}` |
| `GET` | `/api/history` | — | پیام‌های پنجرهٔ فعلی |
| `GET` | `/api/status` | — | وضعیت بارگذاری ASR/TTS |

## محدودیت‌ها (عمدی)

- فقط روی **loopback** اجرا می‌شود؛ این میز توکن REST را اعمال نمی‌کند و برای دسترسی
  شبکه‌ای ساخته نشده است، پس آن را روی LAN باز نکنید.
- **یک عملیات در هر لحظه**: همهٔ مسیرهای مدل‌دار زیر `turn_lock` اجرا می‌شوند؛
  Whisper روی CPU دوهسته‌ای کند است و صف‌شدن باعث تأخیر بی‌معنا می‌شود.
- **حافظهٔ گفتگو:** میز تست همان `Conversation` مسیر زنده را استفاده می‌کند. هر پیام کاربر
  و پاسخ مدل در `data/conversations/<session>.jsonl` (محلی، زیر `PVAI_DATA_DIR`) ذخیره می‌شود،
  و پس از ری‌استارت سرور بارگذاری می‌شود تا مدل چیزهایی مثل نام کاربر را به خاطر بیاورد.
  مدل فقط پنجرهٔ محدود (`PVAI_HISTORY_MAX_MESSAGES` و بودجهٔ `PVAI_HISTORY_TOKEN_BUDGET`)
  را می‌بیند؛ گفتگوی کامل روی دیسک می‌ماند و برای فاین‌تیون قابل بازبینی است.
- **«شروع تازه» فقط پنجرهٔ RAM را خالی می‌کند؛** فایل JSONL را پاک نمی‌کند. حذف گفتگو عملی
  جداگانه است (`python -m server.sessions`).
- برای خاموش‌کردن ذخیرهٔ دیسکی: `PVAI_HISTORY_PERSIST=false`؛ آن‌وقت گفتگو فقط در RAM است.
- `last_pcm` فقط در RAM می‌ماند (روی دیسک نوشته نمی‌شود) و با هر ضبط جدید جایگزین
  می‌شود؛ «شروع تازه» آن را پاک نمی‌کند چون مقایسهٔ تنظیمات به همان ضبط نیاز دارد.
- کیفیت رونویسی همان Whisper-small محلی است؛ اگر متن اشتباه بود، در جعبهٔ رونویسی اصلاح
  کنید یا با بخش ۲ تنظیمات را روی همان ضبط تغییر دهید — این تفکیک «خطای گوش» از
  «خطای مدل» کل هدف این میز تست است.
