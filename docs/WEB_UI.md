# اجرای محیط تست وب (یک‌نوبتی)

این صفحه یک **میز تست** است، نه محصول: یک نوبت «صحبت/تایپ → رونویسی → پاسخ → شنیدن»
را در مرورگر ممکن می‌کند تا بدون ترمینال، خروجی میانی (رونویسی) را ببینید و اگر Whisper
اشتباه شنید، متن را اصلاح و دوباره بفرستید.

## پیش‌نیازها

1. llama-server در حال اجرا باشد (مثلاً `.\tools\start_llama.ps1 -Exe D:\Lama.cpp\bin\llama-server.exe`).
2. `.env` مثل مسیر صوت PC تنظیم شده باشد (مدل Whisper، Piper، آدرس llama-server).

## اجرا

```powershell
.\tools\start_webui.ps1          # یا: python -m server.webui --port 8100
```

سپس در مرورگر همین ماشین باز کنید: <http://127.0.0.1:8100>

## چه چیزی را نشان می‌دهد

| بخش | توضیح |
|---|---|
| وضعیت | ASR/TTS: «در حال بارگذاری…» تا وقتی مدل Whisper در پس‌زمینه لود شود (حدود یک دقیقه روی CPU دوهسته‌ای) |
| دکمهٔ میکروفون | نگه دار و صحبت کن؛ روی رهاکردن، PCM16/16kHz به `POST /api/turn` می‌رود |
| رونویسی | متن شنیده‌شده، **قابل ویرایش**؛ دکمهٔ «ارسال رونویسی» آن را دوباره به مدل می‌دهد |
| تایپ مستقیم | برای تست LLM بدون میکروفون |
| پاسخ | متن پاسخ + پخش خودکار صدا (WAV برگشتی از Piper) و زمان‌های `asr/llm/tts` |
| شروع تازه | تاریخچهٔ کوتاه پنجره‌ای RAM (۱۲ پیام) را پاک می‌کند |

## قرارداد API

| متد | مسیر | ورودی | خروجی |
|---|---|---|---|
| `POST` | `/api/turn` | `{"text": "..."}` یا `{"pcm_b64": "<base64 PCM16 mono 16kHz>"}` | `transcript`, `reply`, `tts_wav_b64`, `timings` |
| `POST` | `/api/reset` | — | `{"status": "ok"}` |
| `GET` | `/api/history` | — | پیام‌های پنجرهٔ فعلی |
| `GET` | `/api/status` | — | وضعیت بارگذاری ASR/TTS |

## محدودیت‌ها (عمدی)

- فقط روی **loopback** اجرا می‌شود؛ این میز توکن REST را اعمال نمی‌کند و برای دسترسی
  شبکه‌ای ساخته نشده است، پس آن را روی LAN باز نکنید.
- **یک نوبت در هر لحظه** پردازش می‌شود: Whisper روی CPU دوهسته‌ای کند است و صف‌شدن باعث
  تأخیر بی‌معنا می‌شود.
- assistant تاریخچهٔ بلند ندارد (۱۲ پیام) و بایگانی JSONL مسیر زنده را نمی‌نویسد.
- کیفیت رونویسی همان Whisper-small محلی است؛ اگر متن اشتباه بود، در جعبهٔ رونویسی اصلاح
  کنید — این تفکیک «خطای گوش» از «خطای مدل» کل هدف این میز تست است.
